# Игровой контур бота: привязка аккаунта + уведомления

Бот-сторона реализована (`src/bot/commands/public.ts`, `subscribers.ts`, `notifier.ts`,
`setup-commands.ts`, `bridge/server.ts`). Ниже — что осталось доделать на стороне сайта
(`go-play-be`) и как всё соединяется.

## 1. Скрытие админ-команд (готово)

`setup-commands.ts` через `setMyCommands` ставит:
- всем приватным чатам — только публичные команды (`/start`, `/link`, `/subscribe`, `/unsubscribe`, `/help`);
- в личках админов/модераторов (`config.yaml → access`) — полный набор.

Сами админ-команды по-прежнему защищены `auth.ts` (ответ «нет доступа» чужим).

## 2. Подписка на уведомления (готово на стороне бота)

- `/subscribe` / `/unsubscribe` — игрок включает/выключает уведомления; chat-id хранятся в `SUBSCRIBERS_FILE`.
  В Docker это `/data/subscribers.json`. Чтобы список пережил редеплой, нужен постоянный диск на `/data`:
  на Railway — **Volume с mount path `/data`** (директива `VOLUME` в Dockerfile там запрещена и ломает сборку),
  локально — `-v goplay-tg-subs:/data`. Без диска бот работает, но подписчики сбрасываются при каждом деплое.
- Рассылка: `POST {BRIDGE публичный порт}/notify` с заголовком `x-notify-secret: $NOTIFY_SECRET`
  и телом `{"text":"<HTML-текст>"}` → бот шлёт текст всем подписчикам.
- Включается только если задан `NOTIFY_SECRET`.
- Эндпоинт отвечает **`202 Accepted` сразу**, рассылка идёт в фоне (троттлинг ~20 msg/s,
  ретрай по `retry_after` на 429). Итог пишется в лог: `sent/failed/removed`.
  Ответ `202` означает «принято к рассылке», а не «все получили».
- Ограничения: `text` до 8192 символов (иначе `413`), битый HTML — вся рассылка автоматически
  уходит plain text'ом. Заблокировавшие бота удаляются из хранилища.
- Health-check: `GET /health` (или `/`) → `{"status":"ok","bridgeConnected":…,"apiClients":…}`.
  Остальные пути отдают `404`.

**Осталось (источник триггера):** кто-то должен дёргать `/notify` при старте ивента.
Варианты:
- сайт (`go-play-be`) при получении события айрдропа/сезона;
- cron/расписание синхронно с `CommandTimer` грифа (тот же момент, что и Discord-алерты в
  `grief/plugins/DiscordSRV/alerts.yml`).

Пример: `curl -X POST "$URL/notify" -H "x-notify-secret: $NOTIFY_SECRET" -H "content-type: application/json" -d '{"text":"🪂 Айрдроп <b>Амбар</b> появился! Спешите за лутом."}'`

## 3. Привязка аккаунта `/link <код>` (нужен эндпоинт на go-play-be)

Бот при `/link <код>` шлёт:

```
POST {WEBSITE_API_URL}/telegram/link
Authorization: Bearer {WEBSITE_API_TOKEN}   # если задан
Content-Type: application/json

{ "code": "<код>", "telegramId": 123456789, "telegramUsername": "nick|null" }
```

Ожидаемые ответы:
- `200 OK` `{ "player": "<MC-ник>" }` — успех (бот покажет ник);
- `400` / `404` — неверный/просроченный код;
- прочее — временная ошибка.

**Осталось на go-play-be:**
1. Колонка/таблица связи `telegramId ↔ player` (рядом с GoCoin/LimboAuth).
2. Генерация кода привязки: в игре командой `/link` (через мост/плагин) или на сайте в профиле —
   короткий одноразовый код с TTL.
3. Эндпоинт `POST /telegram/link`, который валидирует код, сохраняет связь и возвращает ник.
4. (Опц.) Персональные пуши: при наличии связи бэкенд может слать `/notify`-подобные адресные
   сообщения конкретному `telegramId` (напр. «стрик сгорит сегодня», «заказ доставлен»).

## Переменные окружения

См. `.env.example`: `WEBSITE_API_URL`, `WEBSITE_API_TOKEN`, `NOTIFY_SECRET`, `SUBSCRIBERS_FILE`.
Все опциональны — без них соответствующая фича просто выключается, бот стартует штатно.
